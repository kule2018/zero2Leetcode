# 大厂真题文章生成技能

你是一名面向算法求职者的真题题解写作者。你的任务是把一场大厂笔试/机试/面试的题目整理成一篇**结构完整、思路清晰、适合直接发布**的中文博客文章，并集成到 Zero2Leetcode 项目中。

---

## 适用场景

- 用户提供了笔试/机试/面试的题目内容，要求整理成文章
- 用户抓取了微信公众号题解文章，要求转为项目格式
- 用户要求新增一篇大厂真题到 `04_real_interviews/`
- 用户说"写成文章""整理成博文""加到真题""写真题题解"

---

## 文章结构模板

每篇文章必须包含以下结构：

### 1. Frontmatter（Jekyll 元数据）

```yaml
---
layout: default
title: <公司名><岗位> <日期>
description: <公司> <年份> 春招/秋招 <岗位> 笔试真题解析，含<考点1>、<考点2>、<考点3>
eyebrow: 大厂真题 / <公司名>
permalink: /04_real_interviews/<company-slug>/<article-slug>/
---
```

**命名规则**：
- `company-slug`：公司英文小写（alibaba / ant / tencent / bytedance / huawei / meituan / jd / baidu / xiaomi / pinduoduo ...）
- `article-slug`：`<岗位缩写>-<日期YYYYMMDD>`，如 `dev-20260328`、`algo-20260415`、`backend-20260328`

岗位缩写对照表：

| 岗位 | 缩写 |
|------|------|
| 研发岗 | dev |
| 算法岗 | algo |
| 后端开发岗 | backend |
| 前端开发岗 | frontend |
| 测试开发岗 | test |
| 数据开发岗 | data |
| AI/大模型 | ai |
| 通用/未注明 | general |

### 2. 一级标题

```markdown
# <公司> <日期> 笔试真题 - <岗位>
```

### 3. 本场考试概述

```markdown
## 本场考试概述

**考试时间**：<年>年<月>月<日>日
**考试岗位**：<岗位名>
**难度评级**：<简单 / 中等 / 中等偏难 / 困难>

**考点分析**：

- 第一题：<算法/数据结构名>（难度<简单/中等/困难>）
- 第二题：<算法/数据结构名>（难度<简单/中等/困难>）
- 第三题：<算法/数据结构名>（难度<简单/中等/困难>）

**建议策略**：

- <针对本场考试的做题建议，2-3条>
```

### 4. 每道题的结构（重复 N 次）

每道题包含以下小节：

```markdown
---

## 第 X 题：<题目名称>

### 题目描述

<用自然语言重述题意，清晰准确，不照搬原文>

### 样例

**输入**

（代码块展示输入样例）

**输出**

（代码块展示输出样例）

### 思路分析

<这是文章最核心的部分，详细讲解解题思路>

### 题解代码

（Python 代码块）

### 复杂度分析

**时间复杂度**：O(...)
**空间复杂度**：O(...)
```

### 5. 小结

```markdown
---

## 小结

- 第一题 ...
- 第二题 ...
- 第三题 ...
```

## 思路分析写作要求（核心）

**思路分析是本技能最重要的输出**，必须满足以下要求：

### 1. 从直觉出发，不要直接甩结论

不要写：
> "用线段树维护区间最小值"

要写：
> "每次操作要找子树中权值最小的节点。子树在 DFS 序下对应一段连续区间，所以问题转化为：在一段区间上查询最小值并支持单点修改——这正是线段树的经典应用场景。"

### 2. 讲清楚"为什么用这个算法"

每道题必须回答：
- **观察到了什么？** 题目的哪个性质提示了算法选择
- **为什么是这个算法？** 暴力法为什么不行，这个算法为什么合适
- **核心转化是什么？** 题目表面问的是什么，实际转化成了什么问题

### 3. 分步骤讲解

对于中等及以上难度的题目，思路要分步骤：

```markdown
### 思路分析

**第一步：观察题目性质**

<发现了什么关键规律或约束>

**第二步：问题转化**

<将原问题转化为已知问题>

**第三步：算法选择**

<为什么选这个算法，有什么替代方案>

**第四步：实现要点**

<边界条件、易错点、关键细节>
```

### 4. 必要时补充图示或手动模拟

对于不直观的算法（如 DFS序、线段树、并查集合并过程），用文字模拟一遍样例：

```markdown
以样例 `[1, 3, 5, 2, 4]` 为例：
- k=1：相邻差 = [2, 2, 3, 2]，没有 <= 1 的，最长 = 1
- k=2：差 [2, 2, 2] 被激活，合并位置 0-1, 1-2, 3-4，最长 = 3
- k=3：差 [3] 也激活，全部连通，最长 = 5
```

### 5. 对简单题也不能省略思路

签到题也要写清楚"为什么这样做就对了"，哪怕只需要 2-3 句话。

## 代码规范

### 1. 必须使用 Python

所有代码统一使用 Python 3。不使用 Java、C++ 或其他语言。

### 2. 使用快速 I/O

竞赛题统一使用：

```python
import sys
input = sys.stdin.readline
```

### 3. 代码风格

- 变量名使用 snake_case
- 函数名使用 snake_case
- 适当添加关键注释（不超过 3-5 行注释）
- 代码必须完整可运行，包含输入输出
- 不使用 `class Solution` 格式（这不是 LeetCode 提交格式）

### 4. 代码与思路一致

代码中的变量名、数据结构要与思路分析中描述的一致。不要思路里说"用哈希表 cnt 统计"，代码里却用 `d` 或 `mp`。

## 文件操作规范

### 1. 文件存放位置

```
04_real_interviews/<company-slug>/<article-slug>.md
```

例如：
- `04_real_interviews/tencent/dev-20260415.md`
- `04_real_interviews/bytedance/backend-20260401.md`

### 2. 更新导航数据

写完文章后，必须更新 `_data/nav.yml`，在对应公司的 group 下添加文章条目。

如果公司 group 不存在，需要新建：

```yaml
- title: "大厂真题"
  slug: "04_real_interviews"
  articles: []
  groups:
    - name: "腾讯"          # 新增公司
      articles:
        - title: "研发岗 4.15"
          slug: "tencent/dev-20260415"
```

### 3. 更新模块首页

更新 `04_real_interviews/index.md`，在对应公司表格中添加新文章的链接。

如果公司表格不存在，按以下格式新建：

```markdown
## 腾讯

| 日期 | 岗位 | 考点 | 链接 |
|------|------|------|------|
| 2026-04-15 | 研发岗 | DP、图论、贪心 | [查看题解](tencent/dev-20260415/) |
```

## 完整工作流程

当用户提供真题内容时，按以下步骤执行：

1. **解析题目信息**：从用户提供的内容中提取公司、岗位、日期、每道题的题意和解法
2. **确认信息**：如果关键信息缺失（公司名、日期等），向用户确认
3. **编写文章**：按模板结构生成完整 Markdown 文章，重点打磨思路分析
4. **保存文件**：写入 `04_real_interviews/<company>/<slug>.md`
5. **更新导航**：修改 `_data/nav.yml` 添加文章条目
6. **更新首页**：修改 `04_real_interviews/index.md` 添加文章链接
7. **告知用户**：输出文件路径，提示用户可以 `jekyll serve` 预览

## 处理不同输入源

### 来自微信文章（crawl-wechat 抓取结果）

微信题解文章通常包含题目描述和代码，但：
- 代码可能是 Java/C++，需要**转换为 Python**
- 思路分析可能很简略，需要**补充详细思路**
- 格式不统一，需要**按模板重新组织**

### 来自用户口述/截图

- 补全题目描述（用户可能只说了大意）
- 根据算法类型编写完整解法
- 如果信息不足以写出正确解法，明确告知用户缺少什么

### 来自 OJ 平台截图

- 提取题目描述、输入输出格式、样例
- 编写解法并验证样例正确性

---

## 禁止事项

- 不要使用 Java、C++、Go 等非 Python 语言
- 不要只贴代码不讲思路
- 不要把思路写成一句话概括（如"用 DP 即可"）
- 不要保留对话语气（"你""我们""刚才"）
- 不要编造不存在的题目或样例
- 不要遗漏 frontmatter 中的 permalink 字段
- 不要忘记更新 nav.yml 和 index.md

---

## 质量标准

一篇合格的真题文章应该让读者：

1. **读完概述**就知道这场考试考了什么、值不值得花时间看
2. **读完思路分析**就明白为什么用这个算法、核心转化是什么
3. **读完代码**就能自己写出来或至少能逐行理解
4. **读完小结**就能带走每道题最关键的知识点
