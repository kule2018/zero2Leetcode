# LeetCode-128：最长连续序列，O(n) 的关键不是"怎么找连续"，而是"从哪里开始找"

> 配套刷题网站 [Zero2Leetcode](https://onefly.top/zero2Leetcode/) —— 内置本地 OJ + AI 教练，零门槛开刷 Hot 100。

## 一、题目概述

给定一个未排序的整数数组 `nums`，找出其中**最长的连续元素序列**的长度。

要求：算法的时间复杂度必须是 **O(n)**。

### 示例 1

```python
输入：nums = [100, 4, 200, 1, 3, 2]
输出：4
```

解释：最长连续序列是 `[1, 2, 3, 4]`，长度为 4。

---

### 示例 2

```python
输入：nums = [0, 3, 7, 2, 5, 8, 4, 6, 0, 1]
输出：9
```

解释：最长连续序列是 `[0, 1, 2, 3, 4, 5, 6, 7, 8]`，长度为 9。

---

## 二、为什么排序不行

看到"连续序列"，第一反应可能是：先排序，再扫一遍不就行了？

排序确实能做出来，但这道题明确要求 **O(n)** 时间复杂度。

排序最快也是 O(n log n)，不符合要求。

所以这题的核心挑战是：**不排序，怎么找连续序列？**

---

## 三、核心思路：用集合 + 只从起点开始数

这题的关键思想分两步：

### 第一步：把所有数字放进一个集合（set）

集合的查找是 O(1) 的。这样我们就能快速判断"某个数字是否存在"。

### 第二步：只从序列的起点开始往后数

什么是"序列的起点"？就是 **num - 1 不在集合里** 的那个数。

比如数组 `[100, 4, 200, 1, 3, 2]`：

- `1` 的前一个数 `0` 不在集合里，所以 `1` 是某段连续序列的起点
- `2` 的前一个数 `1` 在集合里，所以 `2` 不是起点，跳过
- `3` 的前一个数 `2` 在集合里，跳过
- `4` 的前一个数 `3` 在集合里，跳过
- `100` 的前一个数 `99` 不在集合里，所以 `100` 是起点
- `200` 的前一个数 `199` 不在集合里，所以 `200` 是起点

这样，我们只会从 `1`、`100`、`200` 这三个起点开始计数，而不会对每个数字都重复计算。

从 `1` 开始往后数：`1, 2, 3, 4`，长度 4。
从 `100` 开始往后数：`100`，长度 1。
从 `200` 开始往后数：`200`，长度 1。

最长的是 4，返回 4。

---

## 四、代码实现

```python
class Solution:
    def longestConsecutive(self, nums: list[int]) -> int:
        num_set = set(nums)
        longest = 0

        for num in num_set:
            if num - 1 not in num_set:
                current = num
                length = 1

                while current + 1 in num_set:
                    current += 1
                    length += 1

                longest = max(longest, length)

        return longest
```

## 五、逐行拆解

### 1. 把所有数字放进集合

```python
num_set = set(nums)
```

集合有两个好处：

- 查找某个元素是否存在是 O(1)
- 自动去重（比如数组里有两个 `0`，集合里只保留一个）

---

### 2. 初始化最长长度

```python
longest = 0
```

用来记录目前找到的最长连续序列的长度。

---

### 3. 遍历集合中的每个数字

```python
for num in num_set:
```

注意这里遍历的是 `num_set` 而不是 `nums`。因为集合已经去重了，避免重复数字导致多余的计算。

---

### 4. 判断当前数字是否是序列的起点

```python
if num - 1 not in num_set:
```

这是整道题最核心的一行。

如果 `num - 1` 在集合里，说明 `num` 不是起点，前面还有更小的数能接上，跳过它。

只有 `num - 1` 不在集合里时，`num` 才是某段连续序列的第一个数，值得从它开始往后数。

---

### 5. 从起点开始，往后数连续的数

```python
current = num
length = 1

while current + 1 in num_set:
    current += 1
    length += 1
```

从当前数开始，每次看 `current + 1` 是否存在。存在就继续往后，长度加 1。

---

### 6. 更新最长长度

```python
longest = max(longest, length)
```

每次数完一段连续序列后，和当前最长记录比较，保留更大的。

---

### 7. 返回结果

```python
return longest
```

## 六、手动模拟

以 `nums = [100, 4, 200, 1, 3, 2]` 为例。

### 建集合

num_set = {100, 4, 200, 1, 3, 2}

| 1   | 0 不在            | 是        | 从 1 开始数：1→2→3→4，length = 4 |

| 3   | 2 在              | 不是      | 跳过 |
| 4   | 3 在              | 不是      | 跳过 |

| 200 | 199 不在          | 是        | 从 200 开始数：200，length = 1 |

最终 `longest = 4`。

## 七、复杂度分析

### 时间复杂度：O(n)

这是这道题最容易产生疑问的地方：明明有一个 `for` 循环套了一个 `while` 循环，为什么不是 O(n^2)？

关键在于：**内层的 `while` 循环并不是每次都执行的**。

`while` 只在 `num` 是起点时才执行。而每个数字最多被内层 `while` 访问一次。

举个例子：对于序列 `1, 2, 3, 4`：

- 只有 `1` 是起点，会触发 `while`，依次访问 `2, 3, 4`
- `2, 3, 4` 各自在 `for` 循环里遇到时，因为 `num - 1` 在集合里，直接跳过，不会进入 `while`

所以整个过程中，每个数字只被访问了**常数次**（一次在 `for` 循环中判断是否是起点，至多一次在某个 `while` 中被数到）。

总的操作次数是 O(n)，不是 O(n^2)。

### 空间复杂度：O(n)

需要一个集合来存储所有数字。

---

## 八、总结

这道题的核心思想可以用一句话概括：

> **把所有数字扔进集合，只从每段连续序列的起点开始往后数。**

判断起点的方法极其简单：`num - 1` 不在集合里，就是起点。

这个"只从起点开始"的策略，是保证时间复杂度为 O(n) 的关键。如果对每个数字都尝试往后数，那就退化成 O(n^2) 了。而通过起点判断，每个数字只会被内层循环访问一次，总时间严格线性。

最终的代码只有十几行，没有排序，没有复杂的数据结构，只用了一个集合和一个简单的判断条件：

```python
class Solution:
    def longestConsecutive(self, nums: list[int]) -> int:
        num_set = set(nums)
        longest = 0

        for num in num_set:
            if num - 1 not in num_set:
                current = num
                length = 1

                while current + 1 in num_set:
                    current += 1
                    length += 1

                longest = max(longest, length)

        return longest
```

这道题值得记住的不只是代码本身，而是背后的思维方式：**当你想高效地处理一组数据时，先想清楚"从哪里开始"，往往比"怎么遍历"更重要。**
