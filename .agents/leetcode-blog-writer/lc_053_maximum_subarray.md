# LeetCode-053：最大子数组和，走到每一步都在做同一个决定——是接着走，还是重新开始

## 一、题目概述

给定一个整数数组 `nums`，找到一个**连续子数组**（至少包含一个元素），使其元素之和最大，返回这个最大和。

例如：

### 示例 1

```python
nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
```

输出：

```python
6
```

解释：连续子数组 `[4, -1, 2, 1]` 的和最大，为 `6`。

---

### 示例 2

```python
nums = [1]
```

输出：

```python
1
```

---

### 示例 3

```python
nums = [5, 4, -1, 7, 8]
```

输出：

```python
23
```

整个数组的和就是最大的，`5 + 4 + (-1) + 7 + 8 = 23`。

---

## 二、这题的核心思路

暴力做法是枚举所有子数组，算出每个子数组的和，取最大值。但那样时间复杂度是 O(n²)，太慢了。

这道题有一个非常经典的贪心算法，叫 **Kadane 算法**。它的核心思想只有一句话：

> 走到每个位置时，做一个决定：是把当前元素接到前面的子数组后面，还是从当前元素重新开始一段新子数组。

怎么做这个决定？很简单——看前面累积的和是正是负：

- 如果前面的累积和 `cur_sum` 是正数，那接上它只会让结果更大，所以选择**继续延伸**：`cur_sum + nums[i]`
- 如果前面的累积和 `cur_sum` 是负数或零，那接上它反而是累赘，还不如**丢掉前面，从自己重新开始**：`nums[i]`

用一行代码表达就是：

```python
cur_sum = max(nums[i], cur_sum + nums[i])
```

每走一步，都用 `cur_sum` 记录"以当前位置结尾的最大子数组和"，同时用一个 `max_sum` 记录全局的最大值。遍历一遍数组，`max_sum` 就是答案。

---

## 三、代码实现

```python
class Solution:
    def maxSubArray(self, nums: list[int]) -> int:
        cur_sum = nums[0]
        max_sum = nums[0]

        for i in range(1, len(nums)):
            cur_sum = max(nums[i], cur_sum + nums[i])
            max_sum = max(max_sum, cur_sum)

        return max_sum
```

---

## 四、逐行拆解代码

### 1. 初始化两个变量

```python
cur_sum = nums[0]
max_sum = nums[0]
```

- `cur_sum`：以当前位置结尾的最大子数组和。初始值设为第一个元素。
- `max_sum`：全局最大子数组和。初始值也设为第一个元素。

为什么不初始化为 `0`？因为数组里可能全是负数，比如 `[-3, -2, -1]`，这时候最大子数组和是 `-1`，不是 `0`。

---

### 2. 从第二个元素开始遍历

```python
for i in range(1, len(nums)):
```

第一个元素已经用来初始化了，所以从索引 `1` 开始。

---

### 3. 做核心决策：延伸还是重新开始

```python
cur_sum = max(nums[i], cur_sum + nums[i])
```

这一行就是整道题的灵魂。对于当前位置 `i`，有两个选择：

- `cur_sum + nums[i]`：把当前元素接到前面的子数组后面
- `nums[i]`：抛弃前面所有的累积，从当前元素重新开始

取两者中更大的那个。如果 `cur_sum` 是负数，那 `cur_sum + nums[i]` 一定小于 `nums[i]`，所以自然会选择重新开始。

---

### 4. 更新全局最大值

```python
max_sum = max(max_sum, cur_sum)
```

每一步都检查一下：当前的 `cur_sum` 是不是比之前见过的最大值还大？如果是，就更新 `max_sum`。

---

### 5. 返回结果

```python
return max_sum
```

遍历完整个数组后，`max_sum` 就记录了所有位置中最大的子数组和。

---

## 五、手动模拟

用示例 `[-2, 1, -3, 4, -1, 2, 1, -5, 4]` 走一遍：

初始状态：`cur_sum = -2`，`max_sum = -2`

| 步骤 | nums[i] | cur_sum + nums[i] | nums[i] | 决策 | cur_sum | max_sum |
|------|---------|-------------------|---------|------|---------|---------|
| 1 | `1` | `-2 + 1 = -1` | `1` | 重新开始 | `1` | `1` |
| 2 | `-3` | `1 + (-3) = -2` | `-3` | 延伸 | `-2` | `1` |
| 3 | `4` | `-2 + 4 = 2` | `4` | 重新开始 | `4` | `4` |
| 4 | `-1` | `4 + (-1) = 3` | `-1` | 延伸 | `3` | `4` |
| 5 | `2` | `3 + 2 = 5` | `2` | 延伸 | `5` | `5` |
| 6 | `1` | `5 + 1 = 6` | `1` | 延伸 | `6` | `6` |
| 7 | `-5` | `6 + (-5) = 1` | `-5` | 延伸 | `1` | `6` |
| 8 | `4` | `1 + 4 = 5` | `4` | 延伸 | `5` | `6` |

最终返回 `6`，对应的子数组是 `[4, -1, 2, 1]`。

注意第 3 步：前面累积和是 `-2`，是个负数，带着它反而拖后腿，所以果断从 `4` 重新开始。这正是 Kadane 算法的精髓——**负累积永远不值得保留**。

---

## 六、复杂度分析

**时间复杂度：O(n)**

- 只需要遍历数组一次，每一步都是 O(1) 的比较和赋值操作

**空间复杂度：O(1)**

- 只用了 `cur_sum` 和 `max_sum` 两个额外变量，不随输入规模增长

这是这道题能达到的最优复杂度了——你至少要看一遍所有元素才能知道答案，所以时间不可能比 O(n) 更低。

---

## 七、总结

这道题的核心洞察就一句话：

> 走到每个位置时，如果前面的累积和是负数，就丢掉它，从当前元素重新开始；否则就接着往后累加。

整个解法只有三步：

1. 用 `cur_sum` 跟踪以当前位置结尾的最大子数组和
2. 每一步做一次"延伸 vs 重新开始"的决策
3. 用 `max_sum` 记录遍历过程中见过的最大值

Kadane 算法是动态规划中最经典的入门题之一。它训练的思维模式是：

> 不要试图一次看到全局最优解，而是在每个位置做好局部最优的决策，最后全局最优自然浮现。

`cur_sum = max(nums[i], cur_sum + nums[i])` 这一行代码背后，就是"要不要保留过去"的取舍。把这个思路吃透，后面遇到子数组类的动态规划题（比如最大子数组乘积、环形子数组最大和）都会轻松很多。
