# LeetCode-739：每日温度，单调栈不是"背模板"，而是"让栈里只留还没找到答案的人"

## 一、题目概述

给定一个整数数组 `temperatures`，其中 `temperatures[i]` 表示第 `i` 天的气温。返回一个数组 `answer`，其中 `answer[i]` 表示：从第 `i` 天起，需要等几天才能等到一个更高的温度。如果之后没有更高的温度，则 `answer[i] = 0`。

### 示例

```
输入：temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
输出：[1, 1, 4, 2, 1, 1, 0, 0]
```

解释：

- 第 0 天气温 73，第 1 天就升到 74，等了 1 天
- 第 1 天气温 74，第 2 天就升到 75，等了 1 天
- 第 2 天气温 75，一直到第 6 天才出现 76，等了 4 天
- 第 3 天气温 71，第 5 天出现 72，等了 2 天
- 第 4 天气温 69，第 5 天出现 72，等了 1 天
- 第 5 天气温 72，第 6 天出现 76，等了 1 天
- 第 6 天气温 76，之后没有更高的，答案为 0
- 第 7 天气温 73，之后没有更高的，答案为 0

---

## 二、核心思路

### 暴力做法为什么不行

最直接的想法：对每一天，向后逐个扫描，找到第一个比它高的温度。

```python
for i in range(n):
    for j in range(i + 1, n):
        if temperatures[j] > temperatures[i]:
            answer[i] = j - i
            break
```

时间复杂度 O(n²)，当 `n` 很大时会超时。

### 单调栈的核心想法

换个角度想这个问题：每一天都在"等待"一个比自己更热的未来。如果我们从左到右遍历，遇到一个新的温度时，它可能一次性"解救"好几个之前还在等待的日子。

我们维护一个**栈**，栈里存的是**还没找到答案的日子的索引**。关键性质是：栈里的温度从底到顶是**递减的**（或者说，不会出现底部比顶部小的情况）。

为什么会自然形成递减？因为如果新来一天的温度比栈顶那天还低，它也找不到答案，只能老老实实入栈等着；而如果新来一天的温度比栈顶高，栈顶那天就"等到了"，可以弹出并记录答案。

具体流程：

1. 遍历每一天 `i`
2. 只要栈不为空，且当前温度 `temperatures[i]` **大于**栈顶那天的温度，就说明栈顶那天"等到了"——弹出栈顶，计算等待天数 `i - 栈顶索引`
3. 把当前天 `i` 压入栈（它还不知道自己的答案）

遍历结束后，栈里剩下的都是"永远等不到更高温度"的日子，它们的答案保持为 0。

---

### 一句话总结

栈里存的是"还在排队等更高温度的日子"，新来一天如果够热，就把排在前面的挨个"叫走"（弹出并记录答案），然后自己也加入排队。

---

## 三、代码实现

```python
class Solution:
    def dailyTemperatures(self, temperatures: list[int]) -> list[int]:
        n = len(temperatures)
        answer = [0] * n
        stack = []  # 存索引，栈底到栈顶温度递减

        for i in range(n):
            while stack and temperatures[i] > temperatures[stack[-1]]:
                j = stack.pop()
                answer[j] = i - j
            stack.append(i)

        return answer
```

## 四、逐行拆解

### 1. 初始化答案数组和栈

```python
n = len(temperatures)
answer = [0] * n
stack = []
```

- `answer` 全部初始化为 0——如果某天最终没被弹出过，答案自然就是 0，不需要额外处理
- `stack` 是一个列表，用作栈，里面存的是**天数的索引**（不是温度值本身），因为我们既需要用索引去查温度，又需要用索引算天数差

---

### 2. 从左到右遍历每一天

```python
for i in range(n):
```

`i` 是"今天"，我们要看看今天的温度能不能帮助之前某些天找到答案。

---

### 3. 弹出所有被"解救"的日子

```python
while stack and temperatures[i] > temperatures[stack[-1]]:
    j = stack.pop()
    answer[j] = i - j
```

- `stack[-1]` 是栈顶的索引，代表最近一个还在等待的日子
- 如果今天温度比那天高，那天就"等到了"，弹出它，等待天数就是 `i - j`
- 用 `while` 而不是 `if`，因为今天可能一口气解救好几天——栈里靠近顶部的都是温度较低的，今天只要够热就能连续弹出

---

### 4. 当前天入栈

```python
stack.append(i)
```

不管前面弹出了多少个，当前天 `i` 自己也还不知道未来有没有更热的天，所以入栈等着。

---

### 5. 返回结果

```python
return answer
```

遍历完所有天后，`answer` 数组中的每个位置都已经被正确填写了。

## 五、手动模拟

以 `temperatures = [73, 74, 75, 71, 69, 72, 76, 73]` 为例：

| 步骤 | i | temp[i] | 栈（索引） | 栈对应温度 | 操作 | answer 变化 |
|------|---|---------|-----------|-----------|------|------------|
| 1 | 0 | 73 | [] → [0] | [73] | 栈空，直接入栈 | — |
| 2 | 1 | 74 | [0] → [1] | [74] | 74 > 73，弹出 0，answer[0]=1-0=1；入栈 | answer[0]=1 |
| 3 | 2 | 75 | [1] → [2] | [75] | 75 > 74，弹出 1，answer[1]=2-1=1；入栈 | answer[1]=1 |
| 4 | 3 | 71 | [2] → [2,3] | [75,71] | 71 < 75，直接入栈 | — |
| 5 | 4 | 69 | [2,3] → [2,3,4] | [75,71,69] | 69 < 71，直接入栈 | — |
| 6 | 5 | 72 | [2,3,4] → [2,5] | [75,72] | 72 > 69，弹出 4，answer[4]=5-4=1；72 > 71，弹出 3，answer[3]=5-3=2；72 < 75，停止；入栈 | answer[4]=1, answer[3]=2 |
| 7 | 6 | 76 | [2,5] → [6] | [76] | 76 > 72，弹出 5，answer[5]=6-5=1；76 > 75，弹出 2，answer[2]=6-2=4；栈空停止；入栈 | answer[5]=1, answer[2]=4 |
| 8 | 7 | 73 | [6] → [6,7] | [76,73] | 73 < 76，直接入栈 | — |

遍历结束，栈中剩余 `[6, 7]`，对应第 6 天（76）和第 7 天（73），它们的答案保持为 0。

最终结果：`answer = [1, 1, 4, 2, 1, 1, 0, 0]`，与预期一致。

## 六、复杂度分析

**时间复杂度：O(n)**

- 虽然有 `for` 循环套 `while` 循环，看起来像 O(n²)，但关键观察是：**每个索引最多入栈一次、出栈一次**
- `n` 个元素，总共最多 `n` 次入栈 + `n` 次出栈 = `2n` 次操作
- 所以总时间复杂度是 O(n)，不是 O(n²)

**空间复杂度：O(n)**

- `answer` 数组占 O(n)（这是输出必须的）
- `stack` 最坏情况下存 `n` 个索引（当温度严格递减时，所有天都入栈不弹出），所以栈的额外空间是 O(n)

---

## 七、总结

这道题的标准解法是：

```python
class Solution:
    def dailyTemperatures(self, temperatures: list[int]) -> list[int]:
        n = len(temperatures)
        answer = [0] * n
        stack = []

        for i in range(n):
            while stack and temperatures[i] > temperatures[stack[-1]]:
                j = stack.pop()
                answer[j] = i - j
            stack.append(i)

        return answer
```

最值得记住的三个要点：

- **栈里存索引，不存温度值**：因为我们既要比较温度大小（通过索引查温度），又要计算天数差（直接用索引相减），存索引一举两得
- **单调栈的本质**：栈里维护的是"还没找到答案的日子"，温度从底到顶递减。新元素入栈前，先把所有比它矮的弹出去——这些日子的答案就是当前天
- **时间复杂度是 O(n) 而非 O(n²)**：虽然有嵌套循环，但每个元素只进出栈各一次，总操作量是线性的。这是分析单调栈复杂度的经典思路

这道题是**单调栈**的入门经典题。单调栈的核心模式是"找每个元素左边/右边第一个比它大（或小）的元素"，掌握了这个模式，后面的接雨水（42）、柱状图中最大的矩形（84）等题都会更容易理解。
