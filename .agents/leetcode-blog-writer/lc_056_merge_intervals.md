# LeetCode-056：合并区间，排序之后逐个合并，重叠就延伸，不重叠就新开

## 一、题目概述

给定一个区间的集合 `intervals`，其中 `intervals[i] = [start_i, end_i]`，请合并所有重叠的区间，并返回一个不重叠的区间数组，该数组需要恰好覆盖输入中的所有区间。

什么算重叠？如果一个区间的起点小于或等于另一个区间的终点，它们就有交集，可以合并成一个更大的区间。

例如：

### 示例 1

```python
intervals = [[1,3],[2,6],[8,10],[15,18]]
```

输出：

```python
[[1,6],[8,10],[15,18]]
```

`[1,3]` 和 `[2,6]` 有重叠（2 <= 3），合并成 `[1,6]`。`[8,10]` 和 `[15,18]` 各自独立，不需要合并。

---

### 示例 2

```python
intervals = [[1,4],[4,5]]
```

输出：

```python
[[1,5]]
```

`[1,4]` 和 `[4,5]` 在端点 4 处恰好相接，也算重叠，合并成 `[1,5]`。

---

## 二、核心思路

这道题的关键是：怎么高效地判断哪些区间有重叠？

如果区间是乱序的，比如 `[[1,3],[8,10],[2,6],[15,18]]`，你很难一眼看出谁和谁重叠。但如果**按照起点排序**，情况就完全不一样了：

```text
排序后：[1,3], [2,6], [8,10], [15,18]
```

排序之后，区间是从左到右依次排开的。对于当前区间，它只可能和**前一个区间**重叠，不可能跳过前面和更早的区间重叠而不和前一个重叠。

这样，我们只需要维护一个结果列表 `merged`，然后逐个检查：

> 如果当前区间的起点 <= `merged` 中最后一个区间的终点，说明有重叠，把最后一个区间的终点延伸到两者终点的较大值。
>
> 否则，当前区间和前面的不重叠，直接追加到 `merged` 里。

就这么简单，一次排序 + 一次遍历就搞定了。

---

## 三、代码实现

```python
class Solution:
    def merge(self, intervals: list[list[int]]) -> list[list[int]]:
        intervals.sort(key=lambda x: x[0])
        merged = []

        for interval in intervals:
            if merged and interval[0] <= merged[-1][1]:
                merged[-1][1] = max(merged[-1][1], interval[1])
            else:
                merged.append(interval)

        return merged
```

---

## 四、逐行拆解

### 1. 按起点排序

```python
intervals.sort(key=lambda x: x[0])
```

`key=lambda x: x[0]` 的意思是按照每个区间的第一个元素（起点）从小到大排序。

排序是整个算法的基础。排序之后，起点小的区间排在前面，这样我们只需要和结果列表中最后一个区间比较就够了。

---

### 2. 创建空的结果列表

```python
merged = []
```

这个列表用来存放合并后的区间。随着遍历的推进，它里面的区间一定是互不重叠、从左到右排列的。

---

### 3. 遍历每个区间

```python
for interval in intervals:
```

因为已经排好序了，所以是按起点从小到大依次处理每个区间。

---

### 4. 判断是否重叠

```python
if merged and interval[0] <= merged[-1][1]:
```

这行代码检查两件事：

- `merged` 不为空（第一个区间进来时 `merged` 是空的，直接走 `else` 分支）
- 当前区间的起点 `interval[0]` 小于或等于 `merged` 最后一个区间的终点 `merged[-1][1]`

如果两个条件都满足，说明当前区间和上一个合并后的区间有重叠。

---

### 5. 重叠时：延伸终点

```python
merged[-1][1] = max(merged[-1][1], interval[1])
```

有重叠的话，不需要新增区间，只需要把最后一个区间的终点更新为两者终点中较大的那个。

为什么要取 `max`？因为当前区间可能被上一个区间完全包含。比如 `merged[-1]` 是 `[1,6]`，当前是 `[2,4]`，终点 4 比 6 小，不应该缩小，所以取较大值。

---

### 6. 不重叠时：追加新区间

```python
else:
    merged.append(interval)
```

当前区间和前面的没有交集，它是一个全新的独立区间，直接加入结果列表。

---

### 7. 返回结果

```python
return merged
```

遍历结束后，`merged` 里存的就是合并后的所有区间。

---

## 五、手动模拟

用示例 `[[1,3],[2,6],[8,10],[15,18]]` 走一遍。

### 第一步：排序

```text
排序后：[[1,3],[2,6],[8,10],[15,18]]（本身已经有序）
```

### 第二步：逐个遍历合并

| 步骤 | 当前区间 | 判断条件 | 操作 | merged 状态 |
|------|---------|---------|------|------------|
| 1 | `[1,3]` | `merged` 为空 | 直接追加 | `[[1,3]]` |
| 2 | `[2,6]` | `2 <= 3`，重叠 | 终点取 max(3,6)=6 | `[[1,6]]` |
| 3 | `[8,10]` | `8 > 6`，不重叠 | 直接追加 | `[[1,6],[8,10]]` |
| 4 | `[15,18]` | `15 > 10`，不重叠 | 直接追加 | `[[1,6],[8,10],[15,18]]` |

最终返回：

```python
[[1,6],[8,10],[15,18]]
```

和预期一致。

---

再来一个特殊情况：`[[1,4],[2,3]]`（后一个被前一个完全包含）。

| 步骤 | 当前区间 | 判断条件 | 操作 | merged 状态 |
|------|---------|---------|------|------------|
| 1 | `[1,4]` | `merged` 为空 | 直接追加 | `[[1,4]]` |
| 2 | `[2,3]` | `2 <= 4`，重叠 | 终点取 max(4,3)=4 | `[[1,4]]` |

结果是 `[[1,4]]`，`[2,3]` 被完全吞掉了。这就是为什么要用 `max` 而不是直接赋值。

---

## 六、复杂度分析

**时间复杂度：O(n log n)**

- 排序需要 O(n log n)
- 遍历一次数组需要 O(n)
- 总体由排序主导，是 O(n log n)

**空间复杂度：O(n)**

- 结果列表 `merged` 最坏情况下存了所有区间（没有任何重叠时），占用 O(n) 空间
- 排序的空间开销取决于具体实现，Python 的 Timsort 需要 O(n) 的辅助空间

---

## 七、总结

这道题的核心洞察就一句话：

> 先按起点排序，然后逐个检查——和前一个重叠就延伸终点，不重叠就新开一个区间。

整个解法只有三步：

1. 按区间起点排序
2. 遍历每个区间，和 `merged` 的最后一个比较
3. 重叠就合并（取终点较大值），不重叠就追加

这道题是区间类问题的入门题，也是面试的常客。它训练的核心思维是：

> 面对一堆区间，不要试图两两比较，而是先排序让它们有序排列，然后利用有序性，只和"邻居"比较就够了。

把这个"排序 + 线性扫描"的模式吃透，后面遇到插入区间（LeetCode 57）、无重叠区间（LeetCode 435）等题目都会轻松很多。
